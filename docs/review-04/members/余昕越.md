## 二、所有接口的调用约定

| 项目 | 具体约定 |
|---|---|
| 调试地址 | 挑战 B 默认启动地址为 http://127.0.0.1:8002；实际以启动配置为准 |
| 客户身份 | Cookie：shop_customer_session，由客户登录接口建立；服务端解析客户 ID |
| 登录入口 | 复用 POST /api/a/customer/login，JSON 为 username、password；登录后保存 Cookie |
| POST 请求头 | Content-Type: application/json；X-Requested-With: ShopApp |
| Origin | 若请求携带 Origin，其值必须与服务端协议和 Host 一致 |
| 请求体 | POST 必须提交 JSON 对象；移除接口也必须发送 {}，不能留空 |
| 成功响应 | HTTP 200；读取返回 items，写操作返回 message |
| 失败响应 | JSON 对象，例如 {"error":"请先登录客户账号"} |
| 数据归属 | 服务端从 Cookie 推导客户 ID；请求体不需要 customer_id，也不能借此操作其他客户 |
| 预留规则 | 购物车和收藏不预留库存，结算时由订单服务逐项核对可用数量 |

以下示例中的商品 101、102 均为已准备好的测试商品。GET 示例为字段节选，商品对象还包含分类等信息；POST 示例给出完整业务返回。

## 三、各接口的参数、功能与验证

### YXY-01：查询购物车

**接口：GET /api/b/cart**

参数：无路径参数、查询参数和请求体；使用公共客户 Cookie。

功能：按当前客户查询购物车，按商品编号倒序返回。每一项包含购买数量，以及商品的当前价格、上下架状态、实物库存、预留量、可用量和图片，供页面展示和勾选。

响应字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| items | array | 当前客户的购物车；没有商品时为 [] |
| items[].customer_id | integer | 当前客户编号 |
| items[].product_id | integer | 商品编号 |
| items[].quantity | integer | 该商品在购物车中的数量 |
| items[].name / price_cents | string / integer | 商品当前名称和单价，金额单位为分 |
| items[].product | object | 当前商品信息 |
| product.id / name / price_cents | integer / string / integer | 商品编号、名称、当前单价 |
| product.stock / reserved / available | integer | 实物库存、预留数量、可购买数量 |
| product.status | string | active 在售、frozen 库存全部预留、off 下架 |
| product.images | string[] | 商品图片列表 |

响应节选：

~~~json
{"items":[{"customer_id":1,"product_id":101,"quantity":2,"name":"陶杯","price_cents":1990,"product":{"id":101,"name":"陶杯","price_cents":1990,"stock":5,"reserved":0,"available":5,"status":"active","images":["data:image/png;base64,..."]}}]}
~~~

**验证：**客户甲加入商品后调用接口，应只看到甲的数据；客户乙查询应没有甲的条目。空购物车应返回 {"items":[]}。有效 GET 不带客户会话应返回 401。

### YXY-02：加入购物车或修改数量

**接口：POST /api/b/cart**

| 参数 | 位置 | 类型 | 必填 | 约束与含义 |
|---|---|---|---|---|
| product_id | JSON | integer | 是 | 可转换为 long 的正整数；商品必须存在 |
| quantity | JSON | integer | 是 | 1～1000000；不接受字符串、小数或布尔值 |
| mode | JSON | string | 否 | add 为累加，set 为覆盖；省略或空字符串同 add；去除首尾空白后校验 |

加入示例：

~~~json
{"product_id":101,"quantity":2,"mode":"add"}
~~~

修改示例：

~~~json
{"product_id":101,"quantity":3,"mode":"set"}
~~~

功能规则：

- 商品已在购物车时，add 将请求数量加到原数量；set 直接设置为请求数量。
- 同一客户同一商品只有一条记录；set 在原记录不存在时也会创建记录。
- 单次数量和累加结果都不得超过 1000000，失败时保持原数量。
- 商品不存在返回 404；状态为 off 返回 409。
- 加入购物车不占库存，也不要求购买数量小于当前可用量；已全部预留但未下架的商品仍可加入，实际能否购买由结算判断。

成功响应：

~~~json
{"message":"购物车已更新"}
~~~

响应不直接返回新的购物车项；需要再调用 GET /api/b/cart 读取结果。

**验证：**空车中对 101 先加 2 件、再加 1 件，查询应只有一行且数量为 3；再用 set 设为 5，数量应为 5。提交 quantity=0、1.5、"2" 或 mode="delete" 均应返回 400，原记录不变。

### YXY-03：移除购物车商品

**接口：POST /api/b/cart/{id}/remove**

| 参数 | 位置 | 类型 | 必填 | 含义 |
|---|---|---|---|---|
| id | 路径 | integer（long） | 是 | 商品编号 product_id；不是购物车记录编号 |
| 请求体 | JSON | object | 是 | 发送 {}；无需其他字段 |

请求示例：POST /api/b/cart/101/remove，JSON 为 {}。

功能：同时以客户 ID 和商品 ID 定位删除。只删除当前客户的条目，不影响其他客户。不存在的条目按幂等移除处理，仍返回成功。

成功响应：

~~~json
{"message":"已移除"}
~~~

**验证：**甲乙都将 101 加入购物车；甲移除后，甲列表没有 101、乙列表仍有 101。甲再次移除同一商品应仍返回 200。路径不是数字应返回 400。

### YXY-04：查询收藏列表

**接口：GET /api/b/favorites**

参数：无路径参数、查询参数和请求体；使用公共客户 Cookie。

功能：查询当前客户收藏，按商品编号倒序返回，并附带商品当前信息。已下架的收藏仍可保留，页面可根据 status 提示。收藏不保存购买数量。

| 字段 | 类型 | 含义 |
|---|---|---|
| items | array | 当前客户的收藏；没有收藏时为 [] |
| items[].customer_id / product_id | integer | 收藏所属客户和商品编号 |
| items[].name / price_cents | string / integer | 商品当前名称和单价 |
| items[].product | object | 商品信息，字段与 YXY-01 的 product 一致 |

**验证：**甲收藏 101 后查询应有 101，乙查询不应看到甲的收藏；清空收藏后返回 {"items":[]}。收藏列表不应出现购物车 quantity 字段。

### YXY-05：收藏商品

**接口：POST /api/b/favorites**

| 参数 | 位置 | 类型 | 必填 | 约束与含义 |
|---|---|---|---|---|
| product_id | JSON | integer | 是 | 可转换为 long 的正整数，且商品存在 |

请求示例：

~~~json
{"product_id":101}
~~~

功能：为当前客户创建收藏；重复收藏同一商品保持一条记录。该操作不检查在售状态，允许按已知 ID 收藏数据库中仍存在的下架商品，也不改变购物车或库存。

成功响应：

~~~json
{"message":"已收藏"}
~~~

**验证：**连续收藏 101 两次，收藏列表中应只有一条 101；product_id 为不存在的正整数应返回 404，product_id="101" 应返回 400。

### YXY-06：移除收藏

**接口：POST /api/b/favorites/{id}/remove**

| 参数 | 位置 | 类型 | 必填 | 含义 |
|---|---|---|---|---|
| id | 路径 | integer（long） | 是 | 商品编号 product_id |
| 请求体 | JSON | object | 是 | 发送 {} |

请求示例：POST /api/b/favorites/101/remove，JSON 为 {}。

功能：移除当前客户的指定收藏，不删除商品，也不删除购物车条目。重复移除仍成功。

成功响应：

~~~json
{"message":"已移除"}
~~~

**验证：**同一客户同时收藏并加入购物车 101；移除收藏后，收藏无 101，购物车仍有 101；其他客户的收藏保持不变。

### YXY-07：购物车批量转收藏

**接口：POST /api/b/cart/favorite**

| 参数 | 位置 | 类型 | 必填 | 约束与含义 |
|---|---|---|---|---|
| product_ids | JSON | integer[] | 是 | 1～100 个商品 ID，每项为可转换为 long 的正整数，不能重复，且都在当前客户购物车中 |

请求示例：

~~~json
{"product_ids":[101,102]}
~~~

功能：在同一写事务中，逐项确认商品属于当前客户购物车，添加收藏并去重，再删除对应购物车条目。未选择商品保持不变；收藏仅记录商品，不保留购物车购买数量。列表中任一商品不属于本人购物车时，整批回滚。

成功响应：

~~~json
{"message":"所选商品已移入收藏"}
~~~

**验证：**购物车有 101、102、103，101 已收藏；提交 [101,102] 后，购物车仅剩 103，收藏各有一条 101、102。再以“有效购物车 ID 在前、非法 ID 在后”提交 [103,999999]，应返回 400，103 必须仍在购物车且不得新增其收藏，证明整批回滚。

## 四、异常与边界处理

下表以其余请求条件合法为前提，避免请求先被公共拦截器拒绝而看不到目标错误。

| 场景 | 状态码 | 可观察结果 |
|---|---|---|
| 客户 Cookie 缺失、无效或过期 | 401 | error 提示先登录 |
| 商品 ID 或数量类型错误、数量越界、未知 mode | 400 | 不写入购物车或收藏 |
| product_ids 为空、超过 100 项、重复、含非正整数 | 400 | 不执行批量转移 |
| 批量包含不在本人购物车中的商品 | 400 | 整批回滚 |
| 加购或收藏时商品不存在 | 404 | error 为商品不存在 |
| 加入购物车时商品已下架 | 409 | error 为商品已下架 |
| POST 缺 X-Requested-With 或 Origin 与服务地址不匹配 | 403 | 公共请求边界拒绝 |
| POST Content-Type 不是 application/json | 415 | 请求须为 JSON 格式 |
| POST 请求体为空或大于 3 MiB | 413 | 公共请求边界拒绝 |
| 非法 JSON，或合法 JSON 但不是对象 | 400 | JSON 格式或对象错误 |

移除接口的路径参数由 long 类型绑定；当前业务实现对不存在的编号返回幂等成功，未额外验证路径编号必须大于 0。不能把请求体 product_id 的严格校验规则套用于移除路径。

## 五、与下单模块的衔接

客户通过上述接口准备购物车，再调用 POST /api/b/orders，提交 product_ids 和 request_key，由订单模块读取购物车数量、校验库存并建单。BCollection.selected 也被订单模块复用，用于验证 1～100 个互不重复的正整数商品 ID。

个人提供购物车数据、归属判断、数量校验和批量选择校验；订单创建、总金额、缺货剔除和状态推进由订单模块处理。
