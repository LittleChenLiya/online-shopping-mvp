## 快速开始

保持本文件夹与01～05并列，在项目根目录运行：

```powershell
python -X utf8 -B "06_系统测试/run_tests.py"
```

也可以双击本文件夹的“运行测试.bat”。要求Python 3.10+，不需要第三方包或提前启动购物系统。脚本用随机空闲端口临时启动服务，在独立临时SQLite数据库中测试，结束关闭服务并清理数据库，不访问正式data/shop.db。

## 老师可能问什么

**问：你与第五模块的测试有什么不同？**  
答：第五模块已有6组开发侧回归；本模块复用其环境与助手，再增加并发重复意向、竞争冻结、冲突交易结果、无效操作不写入、非法HTTP、静态路径保护、字段/图片上限和特殊字符保存等8组系统验收。

**问：新增测试有没有改业务代码才能通过？**  
答：没有；只新增06目录，在原系统上构造输入并检查输出和持久化状态。

**问：为什么不能只判断HTTP返回200？**  
答：返回成功不保证数据库正确，所以还检查选中买家、意向状态、商品状态、事件条数，以及无效操作前后数据相同。

**问：并发测试为什么不规定某个买家一定先成功？**  
答：线程调度顺序不确定；要求恰好一个成功，另一个冲突，再验证最终状态与成功操作一致。

**问：这些并发用例能证明所有并发都没问题吗？**  
答：不能，只验证本次两个同时请求的典型竞争场景，不是压力测试或形式化证明。

**问：测试会不会改掉演示数据或密码？**  
答：每个用例新建临时数据库，测试服务独立运行；正式服务是另一个进程，正式数据库不被使用。

**问：全部通过是否意味着系统完全可用？**  
答：不代表。自动化覆盖HTTP/API与数据一致性，浏览器布局、图片预览、确认框等还需按手工清单验证。日志也不能代替屏幕录制视频。

**问：如何定位失败？**  
答：先看test-log.txt的测试方法和断言，再按问题模板记录前提、步骤、实际结果，交给对应模块负责人修复后重新执行。
