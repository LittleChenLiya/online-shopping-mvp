# 小组协作与提交指南

组号、组长、四位成员姓名、最终任务分配、当前评审期次均待定。本页只规定工作方式，不宣称个人已经完成任务。

## 五人任务边界

| 模块 | 拟负责方向 | 成员姓名 |
|---|---|---|
| 01_前端界面 | 全部页面、交互、API 对接 | 待定 |
| 02_商品浏览与购买意向 | 公开商品和购买意向 API | 待定 |
| 03_商品发布与历史 | 商品校验、发布和历史 API | 待定 |
| 04_交易与冻结管理 | 交易状态、冻结、失败恢复和成交 | 待定 |
| 05_卖家账号与系统集成 | 认证、数据库、服务、集成测试和构建 | 待定 |

仓库由组长账号创建；成员 GitHub 用户名确定后，由组长在 Settings → Collaborators 邀请。尚未邀请任何成员。成员自己创建分支，提交真实完成的修改，开 PR，经小组确认后合并。不要代造个人提交、作者身份或已完成工作。

## AI 协作记录

当前基础代码、说明文档和仓库基础设施由 Codex 根据组长请求辅助生成，供小组学习、验证和继续开发。成员应理解实际代码、完成自己的修改与验证，并如实说明 AI 使用。Git 提交不证明某位尚未分配的成员完成了某模块。

## 评审 Wiki

保留固定 Home；每次新增“第N次阶段性评审报告”（1～6次），第7次新增“第7次项目验收报告”。将正式报告链接追加在 Home 评审列表最下面，不覆盖旧报告。

报告基本信息必须先填准确期次、课程日期、组号、项目名称和组长；明确整体计划、项目进度百分比及依据、当前迭代起止时间、目标、任务与成果物。只有个人真实100%完成且有公开成果物的任务进入五列表格。成果物列用公开 Wiki 页面地址，页面再链接到源代码和下载文件；教师意见评审前留空，评审后填写真实点评。

当前只有模板，不能当作已提交的正式报告。姓名确定后让各成员核实任务完成情况，上传自己的成果，再由组长汇总。

## 仍需小组完成的提交物

- 确定基本信息、任务负责人、迭代时间和量化进度。
- 真实的个人完成工作任务表及个人上传的成果下载链接。
- 阶段评审 PPT 讲述版，以及自动测试执行的屏幕录制视频。
- 核实实际构建/镜像和所有页面演示结果。
- 首次在钉钉课程群发送 Wiki Home 地址，后续评审只更新 Wiki；本次没有代发群消息。
- 全员参加答辩，评审后补写教师意见。
