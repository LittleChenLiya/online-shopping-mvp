## 我的任务与边界

负责整个系统的页面和交互：买家商品页、购买意向表单、卖家登录、发布商品与历史、交易管理、修改密码。使用其他四位成员提供的 JSON API，不直接读写数据库。界面禁用按钮只是提示，最终权限和状态由后端检查。

## 关键函数

| 函数 | 参数 / 返回值 | 用途 |
|---|---|---|
| api(path, data) | 接口地址、可选数据；返回 Promise<JSON> | 无 data 发 GET，有 data 发 POST；统一处理错误和安全请求头 |
| render() | 无；异步完成页面更新 | 根据 URL hash 选择页面；进入后台前检查登录；处理加载失败 |
| shop(version) | 本次页面版本 | 查询当前商品，渲染商品或空状态；冻结时禁用购买按钮 |
| buy(version) | 本次页面版本 | 显示买家信息表单并提交购买意向 |
| productAdmin(version) | 本次页面版本 | 显示发布表单、当前商品限制及历史；处理图片预览 |
| tradeAdmin(version) | 本次页面版本 | 展示意向和过程记录，调用冻结、成交、失败接口 |
| accountPage() | 无 | 修改密码与退出登录页面 |
| loginPage() / bindLogin() | HTML 字符串 / 无 | 创建登录表单和绑定提交处理 |
| attachForm(id, handler) | 表单选择器、异步回调 | 阻止默认跳转、读取字段、提交时禁用按钮、统一提示错误 |
| readImage(file) | File；返回 Promise<Data URL> | 检查图片大小、类型并读取内容 |
| esc(value) | 任意值；返回转义文本 | 将特殊字符转为 HTML 实体，避免用户文字被当作标签执行 |
| money(cents) / badge(status) | 整数分 / 状态；字符串 | 格式化价格及状态标识 |
| toast(message, error) | 提示文字、错误标识 | 在页面底部显示成功或失败消息 |
| askConfirm(message) | 确认文字；返回 Promise<boolean> | 使用页面内 dialog 提醒交易后果，确认后才请求后端，取消或 Esc 不执行 |
| intro() / productCard() | 标题等 / 商品对象 | 生成公共标题与商品卡片 |

## 关键变量

- `app`：页面主内容容器，页面切换时替换其内容。
- `labels`：数据库状态英文值到中文界面标签的映射。
- `renderVersion`：每次切页递增；异步请求返回时对比，避免旧请求覆盖新页面。
- `toastTimer`：提示消息自动隐藏的计时器，显示新消息时清除旧计时器。
- `location.hash`：`#shop/#buy/#products/#trades/#account` 表示页面，无需后端提供五套 HTML。

## 老师可能问什么

**问：为什么让一人负责全部前端？**  
答：统一页面风格和请求处理，避免四个后端模块各写一套界面；其他成员按接口约定提供数据即可。

**问：为什么不用前端框架？**  
答：基线只有五类页面，原生 JavaScript 足够完成交互，部署只需要 Python，也方便逐个解释函数。

**问：怎么做到切换页面不刷新？**  
答：监听 hashchange，`render()` 根据 hash 更新主容器；后端提供数据，前端负责渲染。

**问：为什么要 renderVersion？**  
答：网络请求返回顺序可能与切页顺序不同；旧版本响应会被忽略，防止已经离开的页面重新显示。

**问：禁止按钮就能保证不能购买吗？**  
答：不能。用户可以绕过界面调用接口，成员 2 在写入数据库前重新检查 active 状态。

**问：姓名中写入 HTML 会怎样？**  
答：通过 `esc()` 转义后显示为文本；提示使用 textContent，不执行用户输入的 HTML。

**问：提交意向为什么不付钱？**  
答：题目要求线下交钱交货，网页只登记意向和交易结果。

**问：登录信息放在 localStorage 吗？**  
答：没有。浏览器携带服务器设置的 HttpOnly Cookie，JavaScript 不读取会话令牌。
