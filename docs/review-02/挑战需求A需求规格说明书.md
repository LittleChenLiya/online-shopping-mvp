## 2. 项目概述

### 2.1 建设目标

在基线单商品、游客购买意向流程的基础上，提供多商品管理、两级分类、搜索分页、多图与格式化描述、数量库存、客户账号和购买历史等功能。

系统面向单一卖家，客户在线浏览商品、登记购买意向，卖家与客户在线下完成付款和交货。

### 2.2 范围

挑战A包括：

- 多商品发布、展示及库存管理。
- 一级、二级分类维护与分类筛选。
- 商品名称和描述关键词搜索、列表分页。
- 多图展示和受限Markdown描述。
- 客户注册、登录、退出、资料及密码修改。
- 按数量提交购买意向。
- 卖家开始交易、登记成交或失败、拒绝意向。
- 客户取消意向或交易、查询个人历史。
- 卖家查询客户及其购买历史、成交金额。

不包括在线支付、购物车、物流、退款及多卖家入驻。

### 2.3 与基线的关系

基线保留原有单商品和游客意向流程。挑战A使用独立页面和a_*数据表，执行自身业务规则，不自动导入基线商品或购买意向。

## 3. 用户角色与权限

| 角色 | 可执行操作 |
|---|---|
| 游客 | 浏览商品列表和详情、搜索、分类筛选、查看分类、注册和登录 |
| 登录客户 | 游客浏览功能；提交购买意向；修改本人资料和密码；查询、取消本人订单 |
| 卖家 | 管理分类、发布商品、调整库存和上下架；查询和处理订单；查询客户与成交情况 |

客户只能查询、取消本人的订单。客户会话与卖家会话分离；卖家管理接口应验证卖家身份。

## 4. 术语与状态

### 4.1 术语

| 术语 | 定义 |
|---|---|
| 购买意向 | 客户表达线下购买意愿的记录，不代表已经付款或成交 |
| 订单 | 挑战A用于记录购买意向及后续交易过程的数据 |
| 总库存 | 商品尚未成交售出的数量 |
| 预留库存 | 交易中订单所占用的数量 |
| 可用库存 | 总库存减去预留库存 |
| 订单快照 | 提交意向时保存的商品名称、单价、联系方式及交易地点等信息 |

### 4.2 订单状态

| 状态 | 含义 |
|---|---|
| pending | 待处理 |
| frozen | 交易中，已预留库存 |
| completed | 已成交 |
| failed | 未成交，包含卖家拒绝或交易失败 |
| cancelled | 客户已取消 |

### 4.3 商品展示状态

| 状态 | 条件 |
|---|---|
| active | 商品已上架，且仍有可用库存 |
| frozen | 商品已上架、总库存大于0，但库存已全部预留 |
| off | 商品未上架或总库存为0 |

## 5. 功能需求

### A-F01 多商品管理

1. 系统应允许多个商品同时在售。
2. 卖家发布商品时，应填写名称、描述、价格、二级分类、总库存和图片。
3. 商品名称长度应为1～80个Unicode字符。
4. 描述长度应为1～20,000个Unicode字符。
5. 价格应为0.01～9,999,999.99元，最多两位小数。
6. 库存应为0～1,000,000的整数。
7. 零库存商品应保存为下架状态。
8. 卖家应能够查询商品列表，包括下架商品。

验收要点：发布多件有效商品后，应能够同时查询；非法金额、库存或缺少必填项时应拒绝发布。

### A-F02 两级分类管理

1. 系统应支持一级和二级分类，不允许建立第三级分类。
2. 商品必须归入二级分类。
3. 分类名称长度应为1～40个Unicode字符。
4. 同级分类名称不得重复。
5. 卖家应能够创建、改名和删除分类。
6. 分类关联子分类或商品时，应禁止删除。
7. 游客和客户应能够查询分类，用于商品筛选。

示例：

```text
耳机（一级分类）
├── 雷蛇耳机（二级分类）
└── 罗技耳机（二级分类）
```

选择“耳机”时应包含其下属二级分类商品；选择“雷蛇耳机”时只显示该二级分类商品。

### A-F03 商品浏览、搜索与分页

1. 游客无需登录即可浏览商品列表和详情。
2. 公开列表应仅展示已上架且总库存大于0的商品。
3. 系统应支持按商品名称和描述关键词搜索。
4. 系统应支持关键词与分类条件组合查询。
5. 搜索词去首尾空白后不得超过100个Unicode字符。
6. 商品列表默认每页24件，每页数量允许1～100。
7. 页码应为1～1,000,000。
8. 商品应按编号倒序排列。
9. 返回结果应包含当前页商品、匹配总数、页码和每页数量。
10. 商品不存在或已下架时，公开详情查询应返回明确错误。

验收要点：关键词、一级分类、二级分类及组合筛选结果正确；分页不重复、不遗漏符合条件的记录。

### A-F04 多图与格式化描述

1. 每件商品应支持1～6张图片。
2. 图片格式应支持PNG、JPEG、WebP。
3. 单张原始图片不得超过2MB。
4. 图片应保持上传顺序并支持浏览切换。
5. 描述应支持标题、粗体、斜体、列表及商品图片引用。
6. 编辑界面应提供格式工具和预览。
7. 当前格式范围为受限Markdown，不支持视频、任意HTML或外部图片。

文内图片引用示例：

```markdown
![商品细节](image:1)
```

表示引用本商品第1张图片。

验收要点：多图顺序正确；格式及图片引用可展示；非法图片格式、数量和大小应被拒绝。

### A-F05 库存管理

1. 系统应分别展示总库存、预留库存和可用库存。
2. 可用库存 = 总库存 − 交易中订单数量之和。
3. 卖家应能够调整总库存及商品上下架状态。
4. 调整后的总库存不得低于已预留数量。
5. 存在交易中订单时，不允许手动下架。
6. 成交后总库存为0时，应自动下架。
7. 补货后应支持重新上架。
8. 全部库存被预留时，商品仍可展示，但不得接受超过可用库存的意向。

验收要点：库存计算正确；非法调整被拒绝；并发开始交易时不得超额预留。

### A-F06 客户账号

1. 客户应能够自行注册、登录和退出。
2. 注册应填写用户名、密码、电话和默认交易地点。
3. 用户名应为3～40字符，仅允许文字、数字、下划线或横线。
4. 注册密码应为8～128字符。
5. 电话应为6～30字符；客户资料接口当前允许数字、加号、括号、空格和横线。
6. 默认交易地点应为1～200字符。
7. 用户名冲突时应拒绝注册并给出提示。
8. 密码应以哈希形式保存。
9. 客户应能够修改本人电话和默认交易地点。
10. 修改密码应验证原密码，新密码不得与原密码相同。
11. 改密成功后，应使该客户全部旧会话失效。
12. 客户会话有效期为8小时，退出应使当前会话失效。

验收要点：注册登录成功；错误密码被拒绝；改密后旧会话不能继续访问受保护功能。

### A-F07 提交购买意向

1. 挑战A提交意向应要求客户登录。
2. 客户应指定商品和购买数量。
3. 数量应为正整数，不超过1,000,000，且不得超过提交时的可用库存。
4. 电话和交易地点可使用客户资料默认值，也可在提交时指定。
5. 备注可省略，最多300个Unicode字符。
6. 商品不存在、下架或库存不足时，应拒绝提交。
7. 成功提交后，应建立pending订单并返回编号。
8. 提交意向不应扣减或预留库存。
9. 应保存商品名称、单价、数量、电话和地点等订单快照。
10. 应记录提交操作事件。

当前下单接口对显式提供的电话仅校验文本长度6～30，未复用基线电话规范化规则；统一电话校验列入后续完善事项。

验收要点：未登录无法提交；非法数量被拒绝；成功后订单信息正确，库存未被预留。

### A-F08 卖家订单处理

卖家应能够查询订单，并执行以下操作：

| 操作 | 前置状态 | 结果 | 库存影响 |
|---|---|---|---|
| 开始交易freeze | pending | frozen | 预留购买数量 |
| 成交success | frozen | completed | 扣减总库存，解除对应预留 |
| 失败failure | frozen | failed | 释放预留 |
| 拒绝reject | pending | failed | 不扣库存 |

开始交易时必须重新检查可用库存。已结束订单不得重复处理；不符合状态要求的操作应被拒绝。

状态变更、库存修改和事件记录应在同一事务中完成。

### A-F09 客户历史与取消

1. 登录客户应能够分页查询本人全部状态订单。
2. 历史记录应展示商品、数量、价格、联系方式、交易地点及订单状态。
3. 客户仅能取消本人的pending或frozen订单。
4. 取消后状态应变为cancelled。
5. 取消交易中订单应释放预留库存。
6. 已结束订单不得重复取消。
7. 客户修改资料后，历史订单快照应保持不变。

验收要点：客户无法查询或取消他人订单；取消后状态、可用库存和事件记录一致。

### A-F10 卖家客户查询

1. 卖家应能够分页查看注册客户列表。
2. 列表应包含客户基本资料、订单数量和已成交总金额。
3. 已成交总金额应仅统计completed订单。
4. 卖家应能够查询指定客户的全部购买历史。
5. 客户列表和订单历史查询均应验证卖家权限。

验收要点：成交金额计算正确；失败、取消和待处理订单不得计入成交金额。

## 6. 核心业务规则

### 6.1 意向与库存

提交意向只进行单笔数量检查，不预留库存。因此多个待处理意向的合计数量可以超过库存。

卖家开始交易时才进行库存预留，并在事务中检查是否足够。

示例：

1. 商品总库存5，预留0，可用5。
2. 客户提交数量2的意向，库存保持不变。
3. 卖家开始交易，预留变为2，可用变为3。
4. 成交后总库存变为3，预留归零，可用为3。
5. 若交易失败，则总库存仍为5，预留归零，可用恢复为5。

### 6.2 快照与历史

订单保存提交时的商品名称、单价、电话和交易地点。商品或客户资料后续变化，不应改写已有订单快照。

### 6.3 数据一致性

库存与订单状态相关操作应使用数据库事务。操作失败时应回滚，不能出现订单状态已改变但库存或事件记录未更新的部分结果。

### 6.4 当前待教师确认的约定

- 意向提交不占库存，开始交易才预留。
- 挑战A下单要求客户登录。
- 不强制按先来后到顺序开始交易。
- 格式化描述采用受限Markdown。
- 历史订单使用提交时的信息快照。

以上为当前实现采用的规则，教师认可情况按实际评审意见登记。

## 7. 外部接口

接口使用UTF-8 JSON。POST请求应为JSON对象，携带：

```http
Content-Type: application/json
X-Requested-With: ShopApp
```

浏览器请求存在Origin时，应与服务同源。

### 7.1 公开接口

| 方法 | 路径 | 主要参数 |
|---|---|---|
| GET | /api/a/categories | 无 |
| GET | /api/a/products | q、category、page、size |
| GET | /api/a/products/{id} | 路径id |

### 7.2 客户接口

| 方法 | 路径 | 主要参数 |
|---|---|---|
| GET | /api/a/customer/account | 客户Cookie |
| POST | /api/a/customer/register | username、password、phone、default_location |
| POST | /api/a/customer/login | username、password |
| POST | /api/a/customer/logout | 空对象 |
| POST | /api/a/customer/profile | phone、default_location |
| POST | /api/a/customer/password | old_password、new_password |
| POST | /api/a/orders | product_id、quantity，可选phone、trade_location、note |
| GET | /api/a/customer/orders | page、size |
| POST | /api/a/customer/orders/{id} | 路径id；action: "cancel" |

### 7.3 卖家接口

| 方法 | 路径 | 功能 |
|---|---|---|
| GET/POST | /api/a/seller/products | 查询、发布商品 |
| POST | /api/a/seller/products/{id}/stock | 调整库存及上下架 |
| POST | /api/a/seller/categories | 创建分类 |
| POST | /api/a/seller/categories/{id} | 分类改名 |
| POST | /api/a/seller/categories/{id}/delete | 删除分类 |
| GET | /api/a/seller/orders | 查询订单，可按customer_id筛选 |
| POST | /api/a/seller/orders/{id} | freeze/success/failure/reject |
| GET | /api/a/seller/customers | 分页查询客户 |

卖家认证沿用基线账号接口。

### 7.4 错误响应

失败响应格式：

```json
{
  "error": "错误原因"
}
```

| 状态码 | 含义 |
|---|---|
| 400 | 参数类型、长度、格式或操作不合法 |
| 401 | 未登录、会话失效或账号密码错误 |
| 403 | 缺少请求安全标识或Origin不匹配 |
| 404 | 目标资源不存在或不可访问 |
| 409 | 库存、重复数据或业务状态冲突 |
| 413 | 请求体为空或超过统一大小限制 |
| 415 | POST未使用JSON格式 |

## 8. 数据需求

| 数据实体 | 主要内容 |
|---|---|
| 分类a_categories | 名称、父分类关系 |
| 商品a_products | 名称、描述、单价、分类、总库存、上架标识 |
| 图片a_images | 商品关联、图片内容和顺序 |
| 客户a_customers | 用户名、密码哈希、电话、默认地点 |
| 客户会话a_customer_sessions | 令牌哈希、客户关联、过期时间 |
| 订单a_orders | 商品与客户关联、数量、快照、状态 |
| 订单事件a_order_events | 订单、操作、执行者及时间 |

数据应持久化保存，正常重启后仍可读取。挑战A默认使用data/challenge-a.db。

## 9. 非功能需求与约束

| 类别 | 要求 |
|---|---|
| 权限 | 客户只能操作本人订单；卖家管理接口验证卖家身份 |
| 密码与会话 | 密码哈希保存；客户与卖家会话分离；退出和改密按规则失效会话 |
| 输入处理 | 检查JSON类型、长度、数量、金额、图片及状态参数 |
| 数据访问 | 使用参数化SQL，避免直接拼接用户输入 |
| 一致性 | 订单、库存及事件修改使用事务 |
| 持久化 | 重启后商品、客户、订单等数据保留 |
| 可用性 | 页面提供操作结果和失败原因反馈 |
| 可维护性 | Controller与Service分层，共享认证、输入校验及数据库工具 |
| 性能 | 查询支持分页；当前未约定响应时间和吞吐量指标，不宣称已通过性能验收 |

运行环境为Java 17及以上；源码构建需要Maven。前端为HTML、CSS和JavaScript，数据库为SQLite。

图片支持单张2MB，但统一POST请求体上限为3MB，且图片通过Base64传输。当前多图请求仍受整体3MB限制，不表示可以一次上传6张各2MB图片；该约束需在后续联调中明确或调整。
