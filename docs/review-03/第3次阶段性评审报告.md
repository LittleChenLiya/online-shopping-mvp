1. 验证多商品发布、两级分类、搜索分页、图片切换和格式化描述。
2. 验证游客浏览、登录提交意向、客户账号维护和订单访问权限。
3. 验证库存预留、并发防超卖、失败及取消释放、成交扣减和售罄下架。
4. 验证客户资料变化后的订单快照及服务重启后的业务数据。
5. 将需求、测试脚本、运行结果和待确认事项纳入同一评审材料。

## 测试执行结果

Java 构建使用 JDK 17 与 Maven。既有回归 **20 项通过**，覆盖基线交易、输入校验和数据库、密码兼容；本轮挑战 A 另行执行专项验证。两类验证均使用测试环境，专项脚本创建独立临时 SQLite 数据库。

**A01–A10 专项检查全部通过（10/10）**。A03 使用 Edge 实测商品详情页，其余业务场景主要通过已打包 JAR 的 HTTP 接口验证。

| 编号 | 实际结果 |
|---|---|
| A01 | 两件商品可同时浏览，两页返回不同商品；名称和描述均可搜索。 |
| A02 | 一级分类可筛出子类商品，创建第三级返回 HTTP 400。 |
| A03 | 详情页显示标题、加粗、列表及文内图，可切换第二张图；脚本文字未执行。商品通过接口发布。 |
| A04 | 游客提交返回 HTTP 401。库存按总量／预留／可用记录，提交数量 2 后为 5／0／5，开始交易后为 5／2／3。 |
| A05 | 两笔各需 3 件的订单并发请求仅一笔成功，另一笔返回 HTTP 409，库存为 5／5／0。 |
| A06 | 失败和取消分别释放预留；成交至零库存后商品退出公开列表，重复登记成交返回 HTTP 409。 |
| A07 | 注册必填校验生效，可更新交易地点及密码。改密后旧密码失效，退出后不能读取客户订单。 |
| A08 | 客户列表只返回本人订单，尝试取消其他客户订单返回 HTTP 404。 |
| A09 | 卖家能按客户查看订单，客户改资料后旧订单仍保留原商品名、价格、电话和交易地点。 |
| A10 | 重启后仍可登录，分类与交易中订单保留，库存仍为 5／2／3。 |
