## 系统功能与业务规则

基线入口保留单件在售商品及游客意向流程。挑战 A 提供独立的多商品页面与数据表，两种业务入口分别运行各自规则。

| 挑战 A 功能 | 已实现内容 |
|---|---|
| 多商品管理 | 多件商品同时在售，商品详情、列表分页与库存展示 |
| 两级分类 | 一级和二级分类维护，商品归入二级分类，分类筛选及关联删除限制 |
| 搜索 | 按名称、描述关键词搜索，结合分类筛选商品 |
| 多图及格式化描述 | 每件商品支持 1～6 张图片，受限 Markdown 标题、粗体、斜体、列表和文内商品图片，提供预览 |
| 数量库存 | 区分总库存、交易预留和可用库存，成交扣减，失败或取消释放预留，零库存下架 |
| 客户账号 | 注册、登录、退出、个人资料与密码修改 |
| 客户购买历史 | 客户查看本人订单及交易时的联系方式、地点、价格快照 |
| 卖家客户管理 | 客户分页查询、成交金额及指定客户购买历史查询 |

挑战 A 当前采用的库存规则为：提交意向不预留库存，卖家开始交易时预留，成交扣减总库存，失败或客户取消后释放预留，剩余可用库存继续接受购买。商品资料与客户资料的后续修改不改写已有订单快照。

挑战 A 的客户下单需要登录，游客可以浏览。格式化描述采用受限 Markdown，不包含视频和任意 HTML。上述实现边界及库存处理规则在汇报时向教师说明，教师认可情况按实际意见登记。系统不包含在线支付、购物车、物流或多卖家功能。
