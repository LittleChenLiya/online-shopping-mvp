# 挑战 B 运行与合并说明

## 本地运行

Windows双击仓库根目录的启动挑战B.cmd。脚本使用JDK 17和Maven构建，访问 http://127.0.0.1:8002/challenge-b ，默认数据库 data/challenge-b.db。卖家账号 seller，初始密码 seller12345。已有数据库使用原来的卖家密码。

也可运行已构建JAR。

```powershell
java -jar backend-java/target/online-shopping.jar --server.port=8002 --shop.db-path=./data/challenge-b.db
```

需要JDK 17+。Maven和Node只在重新构建或运行测试时需要。可以通过SHOP_DB_PATH选择已有A数据库，新增B表自动初始化，原数据保留。首次试用建议采用本交付默认独立数据库。

## 演示步骤

1. 打开卖家后台登录，建一级和二级分类，发布两件有图片、库存和描述的商品。
2. 客户注册并登录，在商品详情收藏或加入购物车。
3. 购物车修改数量、勾选多个商品，确认提交。
4. 查看一张订单下的商品清单、单价、数量、小计和总金额。
5. 卖家在订单管理依次确认、备货、发货、完成。
6. 另建订单演示客户发货前取消，检查库存释放。
7. 在下单前由卖家调低某商品库存，演示部分缺货仍能为其他商品建单。

## 六人源码上传

每人的压缩包中，payload目录下的路径对应Git仓库根目录。将payload内的文件按路径复制到自己更新后的本地仓库，然后由本人提交。各包的文件所有权互不重叠。

源码基底是主仓库 c48496a（本轮已只读核对远端）。本次新代码由Codex按既定分工协助实现和验证，组员应分别复核、理解并提交所属部件。

推荐使用同一个集成分支按以下顺序合并。各部件有编译和运行依赖，所有源码包合并后统一构建。
1. 曾大君，数据库结构、API适配、静态资源路由和构建启动。
2. 王暾，商品可用库存计算和本轮报告规格。
3. 余昕越，购物车、收藏与批量转移服务。
4. 黄扬轩，订单主明细、下单和状态库存事务。
5. 谢相逸，挑战B页面和交互。
6. 庄云月，测试脚本、日志与截图。

每包外层README_UPLOAD.md列出个人文件及依赖。MANIFEST.sha256用于核对文件内容。
若仓库在c48496a之后已有变动，请逐个比对同名文件后合并。

```powershell
npm ci
npm run test:challenge-b
npm run test:challenge-a
```
