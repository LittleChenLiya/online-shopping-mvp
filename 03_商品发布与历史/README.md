# 成员三：商品发布与历史后端

## 我的任务

`products.py` 负责卖家发布商品、商品信息校验和所有历史商品查询。通过成员 5 的 `require_seller()` 保护接口，通过 `connection()` 访问数据库。界面由成员 1 提供，商品冻结和成交由成员 4 处理。

## 关键函数和变量

| 名称 | 功能 |
|---|---|
| parse_price(request, value) | 接收以元为单位的字符串，用正则限制格式，再用 Decimal 转整数分；拒绝零、负数和超过两位小数 |
| validate_image(request, value) | 检查 Data URL、Base64 编码、PNG/JPEG/WebP 文件头及 2 MB 大小限制 |
| publish_product(request, data) | 验证卖家和字段，在写事务内确认没有未售出商品，插入 active 商品 |
| list_products(request, data) | 验证卖家，按编号倒序返回在售、冻结和已售商品 |
| MAX_IMAGE_BYTES | `2 * 1024 * 1024`，图片原始字节数上限 |
| price_cents | 整数分，例如 19.90 元存为 1990，避免浮点金额误差 |
| ROUTES | `/api/products` 的 GET 和 POST 路由 |

输入限制：name 1–80 字，description 1–2000 字，price 大于零且最多 9999999.99 元。图片必填，前端读取为 Data URL，由本模块校验后存入数据库。文件头检查用于拒绝明显类型不匹配，不是完整图片解码或图片安全扫描。

## 接口及协作

- `POST /api/products`：需要登录；参数 name/description/price/image；成功返回 id/message。
- `GET /api/products`：需要登录；返回 `{products:[...]}`，含 status、created_at、sold_at 等历史信息。
- 字段错误返回 400；存在 active 或 frozen 商品返回 409。

不提供商品删除和编辑接口，避免超出题目的基线功能；成交商品保留历史，成员 4 把其状态改为 sold。默认历史接口一次返回全部记录，数据量很大时可以再扩展分页。

## 老师可能问什么

**问：两个发布请求同时到达，会不会发布两件？**  
答：写事务先取得锁，再检查和插入；数据库还定义了只针对 active/frozen 的唯一索引。自动测试验证两个并发请求只有一个成功。

**问：冻结商品也算占用名额吗？**  
答：算。冻结说明尚未成交，交易失败还要恢复上线；只有 sold 后才能发布下一件。

**问：为什么不用浮点数存价格？**  
答：二进制浮点不能精确表示部分十进制金额。用 Decimal 解析元，再存整数分，展示时除以 100。

**问：图片为什么存数据库？**  
答：这是小规模课程演示，限制每张 2 MB，Data URL 便于统一备份和展示。大量图片时应该改成文件或对象存储，但不属于本次基线。

**问：前端已限制图片格式，后端为什么还检查？**  
答：用户可以直接请求接口绕过前端；后端必须独立校验。

**问：商品售出后去哪了？**  
答：数据库保留原记录和 sold_at；公开查询不显示 sold，后台历史查询仍显示。

**问：为什么历史查询需要登录？**  
答：题目将查看历史商品定义为卖家后台功能，所以后端先验证卖家身份。

## 演示检查

登录发布正常商品；在售时重复发布应失败；冻结时也应失败；成交后可以再发布，历史保留第一件。验证零价格、三位小数和无效图片被拒绝。
