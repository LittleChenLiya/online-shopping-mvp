# 成员二：商品浏览与购买意向后端

## 我的任务

`buyer.py` 提供公开商品信息，以及免注册的购买意向提交。调用成员 5 的 `database.connection()` 和 `public_product()`；由成员 1 的商品页和意向表单调用。单独文件不是完整服务器。

## 关键函数和变量

| 名称 | 功能 |
|---|---|
| get_current_product(request, data) | 查询 active/frozen 的唯一商品；返回 `{product:对象或null}`，已售商品不公开显示 |
| submit_intent(request, data) | 校验商品编号、姓名、电话、备注；在写事务内验证商品在售，然后写入 intents |
| ROUTES | 方法、路径到处理函数的映射，供成员 5 合并路由 |
| product_id | 商品主键，用来关联意向，不能只根据名称关联 |
| contact | 去除空格、括号和横线后的电话号码，用于同商品重复意向检查 |
| result.lastrowid | SQLite 插入后的意向编号，返回买家作为提交凭据 |

输入：product_id 为正整数；buyer_name 1–40 字；contact 原输入 6–30 字符，只允许电话号码相关字符，规范化后主体 6–20 字符；note 可空，最多 300 字。这里只校验电话格式，不发送验证码或验证号码真实归属。

## 接口

- `GET /api/product`：无需登录，返回商品的 id/name/description/image/price_cents/status/created_at，不返回任何买家信息。
- `POST /api/intents`：无需登录；接收 product_id/buyer_name/contact/note，成功返回 id 和 message。
- 商品不是 active、已经下架或者该电话重复提交：409；参数错误：400。

SQL 使用 `?` 占位符绑定参数。唯一约束 `UNIQUE(product_id,contact)` 属于成员 5 的数据库定义，和本模块一起保证同一电话号码不能重复提交同一商品。

## 老师可能问什么

**问：不用注册，买家信息存在哪里？**  
答：直接存在每条 intents 记录中，记录买家姓名、电话、备注和关联的商品，不建立买家账号。

**问：购买意向是订单吗？**  
答：不是。它仅表示想购买，多个买家可以提交；卖家选定其中一个后冻结商品。

**问：商品刚被冻结，买家旧页面还能提交吗？**  
答：不能。`submit_intent()` 在写事务里重新查询商品，只有 active 才插入，旧页面会收到 409。

**问：为什么不用先查询再普通插入？**  
答：那样商品可能在两个操作之间被另一请求冻结。`BEGIN IMMEDIATE` 将检查和插入置于同一写事务，串行处理相关写入。

**问：换一种电话号码格式能重复提交吗？**  
答：空格、括号、横线会先移除，所以这些格式差异不会绕过重复约束；本系统没有验证号码归属，也不承诺识别所有国际号码写法。

**问：别人能查看买家电话吗？**  
答：公开商品接口没有电话字段；只有通过卖家认证的交易管理接口返回购买意向。

**问：为什么用参数化 SQL？**  
答：把 SQL 结构和用户输入分开，输入中的引号不会变成 SQL 指令。
