# 挑战 B 需求规格说明书

版本 1.0，整理日期 2026-11-25。适用本次本地交付。

## 需求依据

依据老师《课程需求》B.1 和 B.2，以及组长转述的两项澄清。
- [课程需求](https://github.com/sebestp/coursewise/wiki/课程需求)
- 一次购物车提交生成一笔订单，包含商品清单、名称、单价、数量和订单总金额。
- 逐项校验库存，缺货项不进入订单，其余商品正常下单。

## 功能及实现部件

| 编号 | 用户行为 | 规则 | 实现 |
|---|---|---|---|
| B-R01 | 收藏商品 | 登录客户添加和移除，重复收藏幂等，按客户隔离 | BCollection.save/remove/list |
| B-R02 | 加入购物车 | 同款合并，支持修改数量和移除；数量为1至1000000的整数 | BCollection.save/remove |
| B-R03 | 批量转收藏 | 勾选的购物车条目移入收藏并去重，多条修改使用同一事务 | BCollection.move |
| B-R04 | 勾选下单 | 1至100种商品，每种一条明细，成功商品组成一张订单 | BOrders.checkout |
| B-R05 | 缺货处理 | 对请求数量不足或已下架的条目提示缺货，保留在购物车；全部缺货不创建订单 | BOrders.checkout |
| B-R06 | 订单清单 | 保存名称、单价、数量、联系方式和地点快照，总金额使用整数分计算 | b_orders、b_order_items |
| B-R07 | 订单流转 | 客户下单→商家确认→备货完成→开始发货→交易完成，卖家逐步推进 | BOrders.action |
| B-R08 | 客户取消 | 客户下单、商家确认、备货完成时可整单取消，发货后拒绝 | BOrders.action |
| B-R09 | 商家取消 | 交易完成前可取消，包括开始发货阶段；重复取消拒绝 | BOrders.action |
| B-R10 | 可靠性 | 客户只访问本人记录，卖家接口独立认证，库存检查与建单原子化，支持请求标识重试 | Database、BController、BOrders |

## 采用的实现约定

下表记录尚未从两条澄清中获得明确答案的边界，供组员复核。它们是当前版本的明确行为。

| 边界 | 本版处理 |
|---|---|
| 请求3件但只剩2件 | 整条商品提示缺货，不自动改成2件 |
| 部分缺货 | 提交前提示处理规则并确认，提交后列出成功订单和缺货清单 |
| 购物车清理 | 只删除成功下单条目，缺货和未勾选条目保留 |
| 全部缺货 | 提示且不创建空订单 |
| 多明细流转 | 整张订单共用一个状态，整单取消 |
| 购物车与收藏 | 登录后使用，持久化到SQLite，同款商品去重 |
| 库存占用 | 加入购物车不预留，下单成功即预留，发货时正式扣减 |
| 发货前取消 | 解除订单预留，实物库存不变 |
| 卖家发货后取消 | 加回已扣减数量并上架，业务上按整单作废处理；实际退回实物仍由线下核实 |
| 完成登记 | 由卖家确认完成，当前版本继续线下结算与交货 |
| 价格 | 下单事务读取最新价格并保存快照，购物车展示当前价格 |
| 重复提交 | 同一客户、同一request_key重放已建订单，不重复建单或重复占库存 |
| 旧A订单 | 保留原A数据、页面和接口，B使用独立订单主表和明细表，商品与账号共享，预留合并计算 |

## 状态与库存

| 当前状态 | 卖家可执行 | 客户可执行 | 库存含义 |
|---|---|---|---|
| 客户下单 placed | 确认、取消 | 取消 | 已预留 |
| 商家确认 confirmed | 备货完成、取消 | 取消 | 已预留 |
| 备货完成 ready | 开始发货、取消 | 取消 | 已预留 |
| 开始发货 shipped | 交易完成、取消 | 查看 | 已扣减 |
| 交易完成 completed | 查看 | 查看 | 已扣减 |
| 已取消 cancelled | 查看 | 查看 | 释放预留或恢复已扣数量 |

## 数据与权限

新增6张独立表，包含购物车、收藏、主订单、明细、缺货反馈和流转记录，另创建订单客户和明细商品索引。所有SQL使用绑定参数。写操作依赖BEGIN IMMEDIATE，事务中读取可用库存、建立订单和明细、移除购物车。库存预留由A冻结订单与B发货前订单明细动态汇总，避免单独计数失配。
