## 1. 目标、范围与角色

系统面向单一卖家。卖家可以同时展示多个商品，客户在线浏览并登记购买意向，买卖双方线下付款和交货。挑战 A 覆盖课程的 **A.1 商品管理升级**和 **A.2 客户升级**。组内个性化开发是**单条购买意向可购买同一商品多件**。挑战 B 的收藏、购物车、备货和发货，以及在线支付、物流、退款和多卖家入驻均在本文范围之外。 [课程需求](https://github.com/sebestp/coursewise/wiki/课程需求)

| 角色 | 可执行用例 |
| --- | --- |
| 游客 | 查看公开分类、商品列表及详情，搜索、筛选、翻页，注册和登录客户账号。 |
| 登录客户 | 使用公开浏览功能，按数量提交购买意向，维护本人资料和密码，查看或取消本人订单，退出登录。 |
| 卖家 | 登录卖家后台，维护分类，发布商品和调整库存、上下架，查看并处理购买意向，查询注册客户及其历史。 |
| 系统 | 校验输入和身份，计算可用库存，记录订单快照及状态事件，持久化业务数据。 |

## 2. 状态与交易流程

正常流程为 **发布商品 → 客户登录并提交意向 → 卖家开始交易并预留数量 → 线下付款和交货 → 卖家登记成交 → 双方查看历史**。

**可用库存 = 总库存 − 预留库存。** 总库存指尚未售出的件数，预留库存是该商品所有交易中订单的数量之和。上架且可用库存大于 0 为可购买。上架且总库存大于 0、可用库存为 0 时仍公开展示，状态为全部预留。未上架或总库存为 0 时，公开列表和详情均隐藏商品。

| 操作者 | 操作 | 原状态 | 结果状态 | 库存变化 |
| --- | --- | --- | --- | --- |
| 客户 | 提交意向 | 无订单 | 待处理 `pending` | 总库存、预留及可用量保持原值。 |
| 卖家 | 开始交易 | 待处理 | 交易中 `frozen` | 总库存不变，预留增加购买数量。 |
| 卖家 | 确认成交 | 交易中 | 已成交 `completed` | 总库存和预留各减少购买数量。总库存为 0 时自动下架。 |
| 卖家 | 登记交易失败 | 交易中 | 未成交 `failed` | 总库存不变，释放本单预留。 |
| 卖家 | 拒绝意向 | 待处理 | 未成交 `failed` | 库存保持原值。 |
| 客户 | 取消本人订单 | 待处理或交易中 | 已取消 `cancelled` | 交易中订单释放本单预留，待处理订单的库存保持原值。 |

已成交、未成交和已取消为结束状态。订单快照在**提交购买意向时**生成。示例中库存按「总量／预留／可用」表示。初始 `5／0／5`，下单 2 件后仍为 `5／0／5`，开始交易后为 `5／2／3`。此后若成交则为 `3／0／3`，若失败或取消则恢复为 `5／0／5`。

## 3. 验收准备与读表方式

从仓库根目录运行 `启动挑战A.cmd`，访问 `http://127.0.0.1:8001/challenge-a`。源码构建需要 JDK 17+ 和 Maven。使用测试数据库，分别准备游客、卖家、客户甲和客户乙四个独立会话。初始测试数据建议建「数码／耳机」「数码／键盘」「家居／杯具」三条分类路径，准备价格 19.90 元、库存 5 件的耳机，以及至少一件其他分类商品。多图验收用两张外观明显不同的图片。

本文共 86 条需求，其中功能需求 79 条，权限、数据与交付约束 7 条。各表的「验证方式与通过条件」使用 **操作 → 预期结果**。证据列中的 A01～A10 指第三次评审脚本实际执行的相关断言，具体范围见第 6 节。**补验**表示应按该行执行并登记结果。各场景有库存或状态依赖时，使用新商品或恢复测试数据后再执行。

### 4.8 卖家处理与客户取消（课程 A.1-3、A.2-2 支撑）

| A-ORD-06 | 卖家可拒绝待处理意向，结果为未成交，库存保持原值。 | 拒绝待处理的 2 件意向 → 历史显示未成交，库存三值与操作前相同。 | 补验 |
| A-ORD-07 | 客户可取消本人待处理订单，取消后状态为已取消，库存保持原值。 | 取消本人待处理订单 → 状态为已取消，库存三值一致。 | 补验 |
| A-ORD-08 | 客户可取消本人交易中订单，取消后状态为已取消并释放本单预留。 | 取消本人已预留 2 件的订单 → 状态为已取消，预留减少 2 件，总库存不变。 | A06 释放库存，状态单独补验 |
| A-ORD-09 | 不符合状态的动作应被拒绝，结束订单不能重复处理。 | 对待处理订单直接登记成交，对已成交订单再次成交或取消 → 409，订单和库存均无二次变化。 | A06 重复成交 409，其余补验 |
| A-ORD-10 | 订单提交、状态变化应记录事件，库存与状态变化应在同一事务中保存。 | 在测试库对照成功操作和失败的竞争请求 → 成功操作留有订单、动作、操作者和时间，失败请求无新事件且订单状态不变。 | 补验 |

### 5.1 接口与数据索引

| 用例 | 入口 |
| --- | --- |
| 公开分类、商品及详情 | `GET /api/a/categories`，`GET /api/a/products?q=&category=&page=&size=`，`GET /api/a/products/{id}` |
| 客户账号 | `GET /api/a/customer/account`，`POST /api/a/customer/{register,login,logout,profile,password}` |
| 客户购买意向与历史 | `POST /api/a/orders`，`GET /api/a/customer/orders`，`POST /api/a/customer/orders/{id}`（`cancel`） |
| 卖家商品与分类 | `GET/POST /api/a/seller/products`，`POST /api/a/seller/products/{id}/stock`，`POST /api/a/seller/categories` 及其 `/{id}`、`/{id}/delete` 子路径 |
| 卖家订单与客户 | `GET /api/a/seller/orders?customer_id=&page=&size=`，`POST /api/a/seller/orders/{id}`（`freeze`、`success`、`failure`、`reject`），`GET /api/a/seller/customers` |

SQLite 实体包括分类、商品、图片、客户、客户会话、订单和订单事件。验收时可用接口回查对外字段，用测试数据库核对密码哈希、订单快照和事件。发布接口的 `price` 使用元金额字符串，例如 `"19.90"`，存储、统计与响应以整数分计算。现有材料未约定响应时间或吞吐量指标。
